## 截图是怎么生成的（说明，便于答辩时回答）

虚拟机是 **Wayland 会话**（`Xwayland :0` + `gnome-shell`），X11 截图工具（`import` / `gnome-screenshot`）无法抓取 Wayland 桌面屏幕（会报 `unable to read X window image 'root'`），且 Wayland 会话的 X 授权也拿不到。

因此采用 **Xvfb 无头虚拟显示 + 真实 xterm 终端** 的方案：

```bash
# 1) 起一个虚拟显示
Xvfb :98 -screen 0 1280x820x24 -nolisten tcp &
export DISPLAY=:98

# 2) 在虚拟显示里开真实终端执行真实命令
xterm -T sio-build -fa 'WenQuanYi Zen Hei Mono' -fs 11 -geometry 152x44 \
      -bg '#0C0C0C' -fg '#CCCCCC' -u8 -e bash /tmp/scenes/s1.sh &

# 3) 等命令真正跑完（脚本会写完成标记），再截整个虚拟屏
while [ ! -f /tmp/scenes/s1.done ]; do sleep 0.5; done
import -window root screenshots/01_build.png
```

关键点：
- 截图内容全部是**虚拟机上程序的真实输出**（真编译、真运行、真日志），不是手工伪造的；
- 每个场景是一个独立脚本，执行完写 `.done` 标记，**轮询到标记后才截图**，避免截到「一半的输出」（第一版就因为截得太早，只拍到 `CC src/sio_bitmap.c` 一行，已重做）；
- 终端字体用 `WenQuanYi Zen Hei Mono` + `-u8`，中文与宽字符正常显示。

## 截图 2 —— 创建空洞 + ls -ls/du/status（`02_sparse_create_status.png`，1280×820）

```bash
W=/tmp/show; rm -rf $W; mkdir -p $W
head -c 4194304 /dev/urandom > $W/src.bin
cd $W && ~/sparseio/sparseio create --target=dl.bin --source=file://$W/src.bin --block=256K --head=64K
ls -ls dl.bin
du -h dl.bin
~/sparseio/sparseio status --target=dl.bin --block=256K --head=64K
```

**截图中的实际输出**（最关键的一张）：
- `逻辑大小 : 4.00 MiB (4194304 字节)`
- `实际占用 : 0 B (0 字节, 0 个 512B 块)`
- `空洞占比 : 100.00% （尚未写入任何数据）`
- `0 -rw-r--r-- 1 lzy lzy 4194304 ... dl.bin` ← `ls -ls` 第 1 列（占用块数）为 **0**，第 5 列是逻辑大小 4194304
- `du -h` 输出 `0   dl.bin` ← 真实磁盘占用 0

## 截图 3 —— 中断 + 中断后的空洞（`03_interrupt_hole.png`，1280×820）

```bash
cd $W
~/sparseio/sparseio write --target=dl.bin --source=file://$W/src.bin --block=256K --head=64K --limit=4
~/sparseio/sparseio status --target=dl.bin --block=256K --head=64K
```

**截图中的实际输出**：
- 逐块显示 `已完成偏移 [ 0 , + 65536)`、`[ 65536 , + 262144)`、`[ 327680 , + 262144)`、`[ 589824 , + 262144)`（头区 64K + 3 个数据块）
- `达到 --limit=4，主动中断以演示断点续传`
- `中断汇总：本次新写入 851968 字节，本次跳过（已完成）0 块，进度已保存到位图`
- `退出码 130（中断，可重新执行 write 续传）`
- status：`实际占用 : 851968 字节 (832.00 KiB)` / **`空洞占比 : 79.69%`** / `分块进度 : 4 / 17 块 (23.53%)`

## 截图 4 —— 断点续传 + 逐块校验 + sha256 一致（`04_resume_verify.png`，1280×820）

```bash
cd $W
~/sparseio/sparseio write  --target=dl.bin --source=file://$W/src.bin --block=256K --head=64K
~/sparseio/sparseio verify --target=dl.bin --source=file://$W/src.bin --block=256K --head=64K
sha256sum src.bin dl.bin
```

**截图中的实际输出**：
- `检测到已有进度位图：已完成 4/17 块，从断点继续` ← 证明是**续传**而不是重下
- 从 `[ 851968 , + 262144)`（块 5/17）继续写到 `块 17/17`，最后一块 `[ 3997696 , + 196608)`
- `全部块提交完成：17 块，本次新写入 3342336 字节，本次跳过（已完成）4 块`
- verify：`已写块 : 17 / 17 块（逐块与源比对一致）`、`空洞块 : 0 块`
- `sha256sum`：源与目标**两行哈希完全相同**（`925372289a9d097699ae678694df7c24c2f9d5f52dd06dc439c10518b43e07a5`）
