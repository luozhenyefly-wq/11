# 编译与运行说明（Ubuntu 22.04.5 LTS）

> 目标环境：Ubuntu 22.04.5 LTS (x86_64)，`gcc 11.4` + GNU `make 4.3`
> 依赖：只用到 libc 与 POSIX，**不需要**任何第三方库（不用 OpenSSL，SHA-256 自带实现）

---

## 1. 编译

```bash
cd sparseio          # 工程根目录
make                 # 默认 -O2，开启 -Wall -Wextra，应为零告警
```

产物：当前目录下的可执行文件 `./sparseio`。

可选：

```bash
make clean && make DEBUG=1    # -O0 -g3 + AddressSanitizer + UBSan，用来复现内存类问题
make install                  # 安装到 /usr/local/bin（需要 sudo）
make dist                     # 打包源码 sparseio-src.tar.gz
```

## 2. 跑测试

```bash
make test        # 6 组用例 T1–T6，输出同时留档到 tests/work/test_all.log
make demo        # 断点续传演示（起本地 HTTP 服务，走真实 206 Range）
bash report.sh   # 一条命令跑完 编译 + 测试 + 演示 + HTTP 冒烟，证据留档到 logs/
```

`report.sh` 跑完会打印「用例通过 / 用例失败」汇总和 4 个证据文件的行数、sha256。

## 3. 手工验证（想自己一步步看的时候）

```bash
# ① 造一个 4MiB 的"服务器端"文件
head -c 4194304 /dev/urandom > /tmp/src.bin

# ② 建 8MiB 空洞文件，看实际占用为 0
./sparseio create --target=/tmp/dl.bin --size=8M --block=256K
stat -c '逻辑=%s 字节  占用512B块数=%b' /tmp/dl.bin
du -h /tmp/dl.bin          # 应该是 0

# ③ 只下 5 块就"断线"
./sparseio write --target=/tmp/dl.bin --source=file:///tmp/src.bin --block=256K --limit=5
echo "中断退出码=$?"        # 应为 130

# ④ 看断点状态 + 空洞
./sparseio status --target=/tmp/dl.bin --block=256K
ls -ls /tmp/dl.bin          # 第 1 列是占用块数，未下载部分仍为 0

# ⑤ 续传（日志里应出现"跳过 N 个已完成块"和"本次新写入 ... 字节"）
./sparseio write --target=/tmp/dl.bin --source=file:///tmp/src.bin --block=256K

# ⑥ 校验 + 对比源
./sparseio verify --target=/tmp/dl.bin --source=file:///tmp/src.bin --block=256K
sha256sum /tmp/src.bin /tmp/dl.bin
```

## 4. 退出码约定

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 2 | 参数/用法错误（含逻辑大小 < 128KB） |
| 3 | 文件 IO 错误 |
| 4 | 区间不可满足（例如目标大小 > 源大小） |
| 5 | 进度位图与当前参数不一致（拒绝静默重下）；也用于校验失败 |
| 6 | 网络错误（HTTP 源不可达等） |
| 7 | 校验不一致 |
| 130 | 被 `SIGINT`/`SIGTERM` 中断（Ctrl-C） |

## 5. 常见问题

**Q：`create` 之后 `du` 显示 0，但 `ls -l` 显示 8MiB，是不是出错了？**
不是。这正是稀疏文件：`ls -l` / `stat -c %s` 是**逻辑大小**，`du` / `stat -c %b` 是**实际占用的磁盘块**。
两者的差值就是空洞。

**Q：`write` 报 `块大小与位图不一致`（exit 5）？**
目标文件的 `<target>.sio` 是用另一组 `--block/--head` 建的。要么改回原参数，要么删掉 `.sio` 与目标文件重新 `create`。
程序故意不让你"换个分块策略继续下"，否则已写数据会错位。

**Q：`write` 报 `目标大小超过源大小`（exit 4）？**
目标文件建大了。按源大小重新 `create`（`--source=` 会自动取源长度），或显式给 `--size`。

**Q：`verify` 提示 `仍有 N 个块未下载`？**
文件不完整，进度位图里还有未提交的块。再跑一次 `write` 续传即可。

**Q：想模拟真实"断线"，怎么让中断点在随机位置？**
用 `--delay=50` 让每块慢一点，然后在终端按 `Ctrl-C`；或者用 `--limit=N` 精确控制已提交块数。
两者都会在**块边界**安全退出并保留进度（退出码 130）。

## 6. 在虚拟机 / 板端运行时的注意点

- 目标目录必须在支持稀疏文件的文件系统上（`ext4` / `tmpfs` 都可以；`vfat`/`exfat` U 盘不支持空洞）。
- 磁盘空间按**实际下载量**预留即可，不需要按逻辑大小预留——这也是本方案的意义。
- 如果要在别的机器上复现，整套工程可以直接拷贝，`make` 即可，无外部依赖。
